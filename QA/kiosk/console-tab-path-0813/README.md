# 35 kioskfleet — פריטי הניווט של הקונסולה על מסלול ה-Tab (#214)

**מה היה שבור.** ששת פריטי הניווט בסרגל הקונסולה היו `<a data-view="…">` בלי `href`.
עוגן בלי `href` אינו אלמנט אינטראקטיבי: הוא אינו מקבל מיקוד, אינו נכנס לסדר ה-Tab
ואינו מגיב ל-Enter. כלומר מי שמנווט במקלדת בלבד לא יכול היה להגיע לאף מסך בקונסולה —
מכשירים, קישורים, הוספת מכשיר, הוראות, ניהול-על, הגדרות. WCAG 2.1.1 (Keyboard), רמה A.
אותו דבר ב-`<a id="logout-btn">`, ו-`<label>שם משתמש</label>` היה בלי `for`, ולכן שדה
שם המשתמש היה חסר שם נגיש.

**1. `js/app.js`** — `e.target.closest('a[data-view]')` → `closest('[data-view]')`.
תואם לאחור: `[data-view]` תופס גם את ה-`<a>` שהיה בייצור באותו רגע, ולכן הפריסה הזו
לבדה אינה משנה התנהגות. אילו הסדר היה הפוך, `console.html` היה נוחת על app.js
שמחפש `a[data-view]` בלבד ואף פריט ניווט לא היה מגיב ללחיצה. אומת שהקובץ החדש חי
(35,833 בייט, `closest('[data-view]')` נוכח, `closest('a[data-view]')` נעדר) **לפני**
שנדחף הקומיט השני.

**2. `console.html`** — ששת פריטי הניווט וה-logout הם `<button type="button">`
(`type` מפורש: בתוך `<form>` כפתור בלי type הוא submit), ו-`<label for="login-user">`.
`style.css` מסגנן `.side nav a` בלבד, ולכן נוספו כללים מקבילים ל-`<style>` שכבר קיים
בעמוד — לא נגיעה בגיליון המשותף, שהוא בשימוש גם ב-`index.html` וב-`install.html`.

## המלכודת שנבדקה ולא נפלה

`.side nav button[data-view] { display: flex }` הוא ספציפיות 0-2-1 מול `.hidden`
שהוא 0-1-0 — כלומר כלל חדש שמגלה את פריט «ניהול-על» למי שאינו אדמין. הוא לא מגלה
אותו, כי `.hidden` הוא `display: none !important` (style.css:206). נמדד בייצור ולא
הונח: הוספת המחלקה בזמן ריצה על הפריט → `display: none`; הסרתה → `display: flex`.

## אימות בייצור (13/08, אחרי שתי הפריסות)

הכתובת היא `more30.com/kiosk/console` ולא `console.html`. `app.js:15` גוזר
`BASE = location.pathname.replace(/\/console\/?$/,'')`, ולכן ב-`/kiosk/console.html`
ה-BASE יוצא `/kiosk/console.html` וכל קריאת API נופלת ל-404 («שגיאה בשרת» במסך
הכניסה). זו אינה תקלה חדשה ואינה קשורה לצעד הזה — היא רק מה שהופך את הכתובת עם
הסיומת ללא-שמישה, ולכן היא רשומה כאן כדי שהבא לא ימדוד שוב את הדבר הלא-נכון.

1. `GET /kiosk/console.html` → 8,944 בייט; 6 × `<button type="button" data-view`,
   0 × `<a data-view`; `<button type="button" id="logout-btn"`; `<label for="login-user"`.
2. עץ הנגישות לפני הכניסה: `textbox "שם משתמש"` — יש שם נגיש (קודם היה בלי).
3. כניסה כ-admin ב-`/kiosk/console` → הסרגל מצייר `navigation` עם שישה `button`.
4. **מקלדת בלבד:** Tab יחיד מה-brand → המיקוד על «המכשירים שלי» (`BUTTON`, `data-view=devices`).
   קודם, Tab יחיד היה מדלג על כל הששה.

## מה שנמצא בדרך ולא נבלע

הכרטיס #214 הורה לדחוף את העותק המקומי של `console.html` (אחרי `app.js`), בהנחה
שעץ המונו-רפו מקדים את הייצור בתיקון הנגישות הזה. **ההנחה נמדדה ולא החזיקה.** העותק
המקומי אינו גרסה אחת קדימה אלא בנייה אחרת לגמרי:

לכן לא נדחף העותק המקומי אלא נערכו קובצי הייצור עצמם, בשתי עריכות כירורגיות
(שורה אחת ב-app.js; התגיות + `for` + כללי CSS ב-console.html). דחיפת העותק המקומי
כמות שהוא הייתה מחליפה את כל הקונסולה החיה בבנייה שמעולם לא רצה בייצור — צעד אחר
לגמרי, לא תיקון נגישות. הפער עצמו נרשם ככרטיס חדש ולא נבלע.

גם שני פרטים בגוף #214 לא החזיקו במדידה: `menu-toggle` (לחצן תפריט לסרגל) אינו
קיים בעותק המקומי, ו-`login.html` אינו קובץ — טופס הכניסה יושב בתוך `console.html`
עצמו, ולכן `<label>שם משתמש</label>` שהכרטיס מיקם «באותו קובץ» אכן שם, ותוקן כאן.
