# 35 kioskfleet — `/kiosk/console.html` היה כתובת חיה שאי אפשר להתחבר דרכה (#215)

**מה היה שבור.** השרת מגיש את הקונסולה בשתי כתובות — `more30.com/kiosk/console`
ו-`more30.com/kiosk/console.html` — ושתיהן מחזירות 200 ואת אותם 8,944 בייט. אבל
`js/app.js:15` גזר את קידומת ה-API מהכתובת שבה העמוד יושב:

```js
const BASE = location.pathname.replace(/\/console\/?$/, '').replace(/\/$/, '');
```

הביטוי מסיר `/console` ו-`/console/` בלבד. בכתובת עם הסיומת ה-BASE יצא
`/kiosk/console.html`, וכל קריאת API נשלחה ל-`/kiosk/console.html/api/…`.
נמדד בייצור לפני התיקון:

| בקשה | תשובה |
|------|-------|
| `GET /kiosk/console.html` | 200, 8,944 בייט |
| `GET /kiosk/console.html/api/config` | **404** |
| `GET /kiosk/api/config` | 200 · `{"wsHost":"kiosk.more30.com","basePath":"/kiosk"}` |

כלומר מי שהגיע לכתובת עם הסיומת ראה מסך כניסה מלא, הקליד שם וסיסמה נכונים, וקיבל
**«שגיאה בשרת»** — הנוסח שב-`api()` נופל אליו כשאין `error` בגוף התשובה (app.js:28).
בשום שלב לא הוצג שהכתובת היא הבעיה, והשרת עצמו החזיר 200 לאותה כניסה בדיוק דרך
הנתיב הנכון. גם ה-WebSocket נגזר מאותו BASE (`${location.host}${BASE}/ws/console`).

**מה זה לא.** דף הנחיתה `/kiosk/` מקשר `<a href="console">` — בלי סיומת — ולכן
המסלול הרגיל מעולם לא נשבר. זו כתובת שמגיעים אליה בסימנייה, בהקלדה ידנית או
בהעתקה מתיעוד, והיא היחידה שהשרת מגיש ו-JS שלה לא עובד.

תואם לאחור — הקבוצה אופציונלית, ולכן כל מה שנגזר קודם נגזר אותו דבר. נבדק ב-node

## אימות בייצור (13/08, אחרי הפריסה)

הכל נמדד על `more30.com` החי עם cache-buster, לא על קובץ מקומי.

1. `GET /kiosk/js/app.js` → 35,844 בייט; הביטוי החדש נוכח, הישן נעדר.
2. **הזרימה שהייתה שבורה, מקצה לקצה בדפדפן:** `kf_token` נמחק מ-localStorage,
   טעינה נקייה של `/kiosk/console.html`, הקלדת `admin` + הסיסמה מ-`core.secrets`
   (`STD_ADMIN_PASSWORD`), לחיצה על «כניסה» → הטוקן נשמר, `#login-err` ריק,
   ו-`h1` = «המכשירים שלי» עם שישה פריטי ניווט. קודם אותה לחיצה בדיוק החזירה
   «שגיאה בשרת». צילום: `console-html-after-login.png`.
3. **בלי רגרסיה:** `/kiosk/console` — `h1` = «המכשירים שלי», שישה פריטים,
   ‏`GET /kiosk/api/config` → 200 · `basePath: "/kiosk"`.
4. `GET /kiosk/console.html/api/config` עדיין 404 — וזה נכון: הנתיב הזה באמת אינו
   קיים בשרת. מה שהשתנה הוא שהדפדפן כבר אינו בונה אותו.

## מה שנמצא בדרך ולא נבלע

בצילום נראה שכפתור הפעולה הראשי של המסך הראשון — **«➕ הוספת מכשיר»** — מכוסה
בידי כדור הכניסה המשותף (`<more30-auth>`, shadow DOM). נמדד ולא הונח: הכדור
`t=12 l=16 r=92 b=48`, הכפתור `t=29 l=34 r=155 b=60`, ו-`elementFromPoint` במרכז
החפיפה מחזיר `MORE30-AUTH` — כלומר הלחיצה נוחתת על הכדור. `--more30-auth-inset`
מוגדר כאן `104px` אך הקונסולה אינה משתמשת בו. זה בדיוק הליקוי שתוקן ב-03/08 על
11 מסלולים, ו-`/kiosk/console` לא היה בהם. נרשם כ-**#216** — לא תוקן בצעד הזה,
כי הוא ברמת הפורטל ולא ב-zol, ותיקונו הוא צעד אחר.

הבאג של ה-WebSocket שנראה בקונסולת הדפדפן (`wss://kiosk.more30.com` →
`ERR_NAME_NOT_RESOLVED`) קדם לצעד ואינו קשור אליו — הוא מגיע מ-`wsHost` שהשרת
מחזיר ב-`/api/config`. הקונסולה עובדת בלעדיו (הסוקט הוא המסלול המהיר, לא היחיד).
