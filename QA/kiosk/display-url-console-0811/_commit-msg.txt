KIOSK_BUILD §2★א, console side. The column, the validation and the PATCH landed
last round; the console still drew one URL field, so "קישור שיוצג על המכשיר" was
reachable only by hand-writing an HTTP call — and it is the field an owner
touches most, to point a single tablet at a sub-page.

The edit dialog now has "אתר ראשי" and, under it, "קישור שיוצג על המכשיר". The
first field's old label named both jobs ("קישור האירוע/אולם (Home URL)") back
when one column did both, so it is renamed rather than left describing the pair.

displayUrl is sent on every save, empty included: the server reads it by presence
because '' is how the field is cleared, and an omitted key would leave a device
permanently pinned to whatever link it was once given.

The hint under it is recomputed from the live host list instead of written once,
so an owner who edits the domain list in the same dialog is told whether the
automatic widening still applies. The card grows a 📺 line only when the device
has a link of its own — mapDevice reads display_url ?? displayUrl ?? null, with
??, because "following the main site" and "given its own link" have to stay
distinguishable there. Both URLs are wrapped dir=ltr; they now follow a Hebrew
label on one line, where bidi reorders them.

Verified in QA/kiosk/display-url-console-0811/ — 9 cases in a real browser
against a stub that rewrites only the express glue and calls the real
displayurl.js/approvals.js/hosts.js in the order routes/devices.js calls them.
Asserted on both sides of each save: the stored column and the update_config
pushed to the device. A display link widens what is pushed but never the stored
allow-list; clearing stores NULL, not a copy of the main site; a link typed
identical to the main site collapses to NULL; javascript: and a scheme-less host
are refused in Hebrew with the modal left open and nothing pushed.
