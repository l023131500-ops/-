`screens-enrol-settings-0811` closed item 6 and wrote down one thing as open
rather than closed, because no contrast ratio can answer it: `a {
text-decoration: none }` meant the console's three in-text links differed from
the text around them in hue alone. Measured in this run rather than assumed —
the paragraph holding the guide link is `--muted` at 16px/400 and the link was
16px/400 too, so the underline was the whole of the missing difference. Anyone
who does not separate `--link-ink` from the ink beside it does not see that
there is a link there.

One rule in `css/style.css`:

  p a:not(.btn), .alert a:not(.btn), li a:not(.btn) {
    text-decoration: underline; text-underline-offset: .2em;
  }

- **the global default stays `none`.** Flipping it is the obvious move and is
  wrong here: it draws a line under all seven sidebar items, under every `.btn`
  in the console and under five `.btn`s on the marketing page — a worse screen
  than the one this fixes. The three in-text links that exist all sit inside a
  `p` or inside `.alert`, and all three are measured.
- `:not(.btn)` is kept even so, because a button inside running text is a shape
  that exists: `.plan a.btn` sits after `<ul><li>` on the marketing page. That
  row is graded too.
- navigation is not underlined, and that is the same standard rather than an
  exemption taken quietly: 1.4.1 is about telling a link apart from the text
  around it, and `.nav-links` / `.side nav` / `.skip` are not in text.
- `text-underline-offset` for the descenders of the Hebrew face, and for the
  install link, which is `word-break: break-all` and wraps mid-URL.
