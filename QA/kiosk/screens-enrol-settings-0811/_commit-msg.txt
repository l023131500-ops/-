What failed is a global declaration these screens merely exposed. a { color:
var(--accent) } — and --accent is a brand colour that does not invert, so on
the dark card #131c2e it is 3.22:1, under the 4.5:1 normal text needs. The
--label-ink pattern exactly: a fixed value beside a surface that moves. Three
such links exist in the console and all three are measured here — the guide
link, the login card's back-to-site link (unhidden to be graded), and the
install link inside .alert-ok. Light mode does not move, 5.28:1 before and
after; the defect was dark-only.

Two tokens, not one, and the third link is why. .alert-ok is one of the light
chips: its fill stays light on a dark card, so the one link that was already
fine is the one on a surface that does not invert, and a lightened ink on it is
2.18:1. One inverting token would have fixed two links and broken the third —
which is also the one that matters most, since the install link is what gets
sent to whoever is holding the tablet. So --link-ink inverts (#2a61e8 light,
identical to --accent so the light console does not move; #7ea6ff dark, the
value already chosen for --accent-control, deliberately, so the dark console
keeps one blue) and --chip-link-ink does not. #1f4fd8 rather than
--chip-accent-ink for a measured reason: .alert is two families, and on
.alert-error's pink #2a61e8 is 4.33:1, so a link added to an error alert would
have failed silently. 6.03:1 on #dcfce7 and 5.43:1 on #fee2e2.
