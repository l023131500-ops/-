Item 5 of apps/35-kioskfleet/STATUS.md "Next, in order" — items 1-3 are still

kiosk-launcher.html is the one page of this service that renders full-screen on
a tablet, read at arm's length by someone typing a six-character code off a
printed card. Every contrast pass so far opened a dialog in the console.

It also cannot be measured the console's way: here nothing is opaque, so "walk
up to the first opaque background" lands on body's navy — the darkest thing on
the page — and every ratio comes out flattering. The backdrop is now sampled
from the pixels Chromium actually painted, and translucent foregrounds are
composited over that measured value.

Three real defects, in public/kiosk-launcher.html only:
  - #code::placeholder at 2.70:1. The only thing on the screen saying the code
    is six characters long, read before anything is typed. .3 -> .55 = 5.78:1.
  - .choice at 1.83:1. Every row of the selection screen, and the row is the
    control. .2 -> --edge .45 = 3.60 / 3.95:1. Hover was .4, i.e. below the new
    resting value, so hovering a row made its outline fainter; now .62.
  - the primary button at 2.51:1. .btn declares border: none, so the fill is the
    boundary — and no solid fill satisfies both constraints at 17px (white text
    wants 4.5:1 from the inside, the card wants 3:1 from the outside; they cross
    at L~0.185). So the label became WCAG large text (19px/700) and the fill
    moved to #3d74ff: 3.24:1 against the card, 4.09:1 under the label.
    --accent itself is untouched; the console still uses it.

QA/kiosk/launcher-contrast-0811 — a real Chromium at both colorScheme values
against launcher-display-url-page-0811's stub, reused rather than copied. 23/28
graded rows pass; the five failures are the "before" rows, re-injected into the
same DOM in the same run. Four screenshots. 152 tests, 151 pass — the documented
baseline, unchanged, since this step adds no server code.

Two harness bugs found and fixed in that run: the input is focused on load, so
the first read reported the green focus ring as the resting border — which is
how .25 survived this whole build unmeasured; and transition: .15s covers color,
so a read in the tick after the text-hiding style is removed returns a value
part way back from transparent (rgba(255,255,255,0.74) for the button's label).
check() now throws on any non-opaque colour reaching it, since lum() reads three
channels and would have graded it flatteringly and silently.

Left with numbers rather than silence: the card edge (1.54:1) and the alert are
separators, which 1.4.11 exempts; the four .ico tints (1.37-1.77:1) are not the
sole carrier of which row is which — each row also has its own emoji and a name.

Not deployed. #35's source is gitignored here, so the page change is recorded in
STATUS.md; the Railway service still serves the previous version.
