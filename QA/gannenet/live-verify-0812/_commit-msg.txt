The bug the browser turned up is in app/api/drive/[id]/route.ts, which streams the
2,719 Drive-backed items of the 2,977-item shelf. It passed the upstream
Content-Type straight through, and drive.usercontent.google.com answers every one
of them application/octet-stream — while the same route sends
Content-Disposition: inline for viewing. A browser honours inline only for a type
it can render, so "פתיחה בכרטיסייה חדשה" downloaded the file instead of showing
it, on every Drive-backed item. The catalog knew the real type the whole time
(mime: application/pdf) and only the download filename was reading it; it is now
the Content-Type, with upstream kept as the fallback. /api/shelf/<name>.pdf was
already correct — the two routes serve one shelf and now agree.
