gannenet (40): the download button kept a second copy of every file, and neither copy could be updated

`downloadUrl()` appends `?dl=1`, and `dl` changes exactly one response header:
/api/shelf, /api/drive and /api/upload answer `inline` without it and
`attachment` with it. `isFile()` matched that URL too, so `cacheFirst` filed it
in FILES as a file of its own -- a second full copy of every file a teacher
downloaded, differing from the viewer's copy in one header. And because
`cacheFirst` returned any hit before looking at the request's cache mode, that
copy's headers were frozen: once the routes learned each file's real name
(14a8f29), a browser that had already downloaded the file went on saving it
under its Drive id, and even fetch(url, {cache:"reload"}) could not get past the
cache. Only a URL that had never been seen could.

downloadVariant(): a `?dl=1` request is never stored and always goes to the
network; offline it falls back to the bare copy in FILES, re-headed to
`attachment` so the button still saves rather than opens. cacheFirst() honours
the request's cache mode -- reload/no-store/no-cache skip the hit and replace
the entry, force-cache/only-if-cached stay cache-first, and a reload that cannot
reach the network still returns her copy. dropDownloadVariants() clears the
`?dl=1` entries already out there on activate -- deliberately not a FILES bump:
"שמירת התצוגה לאופליין" prefetches the bare URLs (app/shelf/page.tsx), so her
offline material is untouched and only the duplicate is released.

Measured on the production build against the real bucket. A FILES seeded to look
like a pre-change browser now answers the download with the live header
(decoding to "הופה, סוף שנה כבר כאן! - דוגמא לעמוד מתוך הקטלוג.png") and the
real 20,481 bytes. Through the real UI on a clean browser, view + download leave
one cache entry where they used to leave two. A seeded stand-in is still served
to a plain fetch and replaced by {cache:"reload"}. With the server stopped and
the port confirmed closed, a saved file still views and still downloads from
cache, and a file never saved fails as before. Three legacy dl entries dropped at
activate, bare copy kept -- note unregister()+register() of a byte-identical
script does not reinstall (the browser reuses the running worker and activate
never fires), so that reads as a false no-op; a distinct script URL on the same
scope forces the real install. tsc --noEmit 0; bucket left as found.

Cost, stated plainly: a file downloaded but never viewed and never saved for
offline loses its cached copy at activate; online it returns on the next click.

Evidence in QA/gannenet/sw-download-variant-0811/. sw.js.after carries the worker
source itself, which /apps/** keeps out of the tree.
