# gannenet (40) — the upload form promised four times what the platform accepts

`/shelf/upload` said **"PDF או תמונה, עד 25MB"** and `POST /api/catalog` checked
`file.size > 25 * 1024 * 1024`. The request body of a Vercel Function may not
exceed **4.5 MB**; past that the platform answers **413
`FUNCTION_PAYLOAD_TOO_LARGE`** and the function is never invoked
([docs](https://vercel.com/docs/functions/limitations#request-body-size)). So the
route's own check could only ever run for files the edge had already let through,
and everything between 4.5MB and 25MB — which the page invited — was uploaded in
full over the teacher's connection and then refused by something that does not
speak this app's language.

What she saw at that point was not a sentence. The edge answers HTML, the page
did `const data = await res.json()`, and `Response.json()` on HTML throws:

    SyntaxError: Failed to execute 'json' on 'Response':
    Unexpected token '<', "<!DOCTYPE "... is not valid JSON

— and `catch (err) { setMsg({ text: err.message }) }` printed exactly that, in
the middle of a Hebrew form. Measured in the same browser, not reasoned about.

## What ships

- **`lib/upload-limits.ts` (new)** — one number, read by the form and the route.
  **4 MB**, which leaves the multipart envelope (boundaries + title, category,
  sender) room under the 4.5 MB the platform counts. It costs nothing against
  the material this shelf holds: the 258 seed files average **622 KB** and the
  largest is **1,944 KB** (`content/catalog.json`), so nothing already on the
  shelf would have been refused at this limit. Raising it means moving the bytes
  off the request body — a signed upload straight to Storage — not raising the
  number.
- **`app/shelf/upload/page.tsx`** — the file is checked when it is *picked*, so
  an oversized one never leaves the browser, and the message names the file's own
  size. Errors are read once as text and parsed only if they are JSON, with a
  status fallback (413 / 503 / 5xx / other), so the edge's HTML reads as Hebrew.
  A failed `fetch` (a `TypeError`, "Failed to fetch") gets its own sentence
  instead of the browser's. Both labels and the copy read the shared constant.
- **`app/api/catalog/route.ts`** — same constant, and **413** rather than 400,
  matching what the edge would have said.

## Open

- The limit is the platform's, not the product's. If a gan needs to upload a
  scanned booklet over 4MB, the fix is a signed upload straight to Storage from
  the browser — which is also the one thing that would put the anon key, or a
  short-lived token for it, in front of the client. Not done here; it is a
  design decision, and nothing on the shelf today needs it.
- The response body carries the same 4.5 MB ceiling, and `/api/shelf/[name]` and
  `/api/upload/[name]` stream files through it. No seed file is close (max
  1,944 KB), and an upload can no longer exceed 4MB, so nothing on the shelf can
  reach it today.
