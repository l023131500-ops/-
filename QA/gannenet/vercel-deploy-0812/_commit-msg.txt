Two builds failed first, on one character: `Specified basePath has to start with
a /, found "﻿/gannenet"`. A U+FEFF sat in front of the value, and not because
.env.local carries one — PowerShell 5.1 encodes what it pipes into a native
command's stdin with [Console]::OutputEncoding, which emits a UTF-8 BOM, so
`$value | vercel env add` stored `﻿<value>` for every variable; APP_BASE_PATH is
just the one Next validates loudly. Forcing a BOM-less UTF8Encoding($false)
before the pipe did not help (second failed build, identical error). What worked
was deleting all twelve entries and POSTing them to the REST API as a UTF-8 JSON
body, which never crosses a console encoder. The values cannot be read back to
check — `vercel env pull` prints [SENSITIVE] and the API returns value:null for
encrypted vars — so the build is the only test.

ssoProtection is all_except_custom_domains, byte-identical to galil-more30 and
every other mount project: the hashed deployment URL 302s to SSO, the project
alias is open, and that alias is what the portal rewrites proxy to — so the next
step needs no protection change.
