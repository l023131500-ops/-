Root cause, client.functions.ts:131 — the write goes to
client_profiles.uploaded_documents AS THE CLIENT, and client_profiles
has RLS with only "Clients read own client profile" (SELECT) and an
admin-only FOR ALL policy. There is no policy letting a client UPDATE
their own row, so RLS filters the UPDATE to zero rows — and an UPDATE
affecting zero rows is not an error in PostgREST. `if (upErr) throw`
never fires; the handler reports success for a write that did not
happen. The column-level GRANT UPDATE (uploaded_documents) from
migration 20260605003212 is what makes this look correct on inspection:
a GRANT is not an RLS policy.

The right table already exists and is unused. Migration 20260610185015
created public.documents with `doc_all FOR ALL USING/WITH CHECK
owner_client_id = auth.uid()` — which a client does pass — and even
backfilled the old jsonb "kept for one release". All three server
functions stayed on the old column.

public.documents plus a build and deploy of 31 does not fit one step.
