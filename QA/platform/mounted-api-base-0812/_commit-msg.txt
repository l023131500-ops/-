platform (#154): the last two mounts were candidates, not bugs — read in the bundle and then in a browser

#154 was down to two: imud (04) on /api/books and /api/meta, kupot (28) on
/api/agent and /api/switch-lead. Both carried the candidate verdicts the script
refuses to call proof — the route answers under the mount, and that says nothing
about whether the shipped client gets there, because the prefix is applied at the
call and never written into the literal. Exactly studio's standing until 8537099
read its call site.

Both bundles have studio's shape with one wrapper: v2 = z1 && z1.trim() ? … : Nx,
where Nx is "/imud/" stripped of its trailing slash (Vite's BASE_URL, inlined by
8507410 for imud and 6551b75 for kupot) and z1 is Cx?.VITE_API_BASE off an empty
object literal. readCallSite had no rule for a property read off an object, so
the override was unknown, and an unknown condition leaves the base undecided.

Two symbols, kept apart from null on purpose: EMPTY_OBJECT for a bare {} and
ABSENT for a property read off one. null still means "could not read this" and is
never allowed to act like "provably empty" — the override grants the base only
when it resolves to ABSENT, because a build that did set VITE_API_BASE would take
the other branch and the base would be its value. Negative controls in the same
run: mechiron and smel still resolve "" and get no grant, and /studio/api/brands
still answers JSON.
