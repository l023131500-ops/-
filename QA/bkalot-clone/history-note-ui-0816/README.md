## מה היה חסר

ו-`decided_at` נדרסים בכל `UPDATE` — והרצף מתחתיה נוקב בשני הנימוקים, כל אחד על

## פתוח

**שתיים, ובסדר הזה.**

1. **תיבת הנימוק.** אין ב-`admin.html` שדה להקליד נימוק לפני «שינוי סטטוס» —
   הכתיבה קיימת בשער מאז 0090 ופתוחה לכל מי שיודע לשלוח בקשה, ואינה קיימת
   למנהל שיושב מול המסך. זו הלבנה הבאה (UI), והיא כוללת את מה שהתצוגה לא צריכה:
   ספירת תווים מול תקרת 500, ומה קורה כש-`note_too_long` חוזר.
2. **הפריסה.** מה שנמדד כאן הוא הקוד שבמקור; בייצור שלושת המסומנים החדשים הם 0
   בשתי הכתובות, כלומר מסך הפנייה עדיין אינו מצייר את הנימוק. אותו פיצול כמו
   0088 → 8a577bc → c3b7c45.

מה שלא נבנה: אין חובת נימוק על `rejected`; אין עריכה ואין מחיקה (היומן
insert-only); אין חיפוש בטקסט הנימוקים ואין סינון «יש נימוק / אין»;
`bkalot_clone_admin_cases` אינה יודעת על השדה ולא תדע — שורת רשימה אינה מקום
לטקסט חופשי של 500 תווים; ואין backfill ולא יהיה — שורות מלפני 0090 נושאות
`note` null לנצח. וממה שקדם: אין סינון ואין מיון לפי מספר מעברים; אין
`status_last_change_at`; אין שמות ברשימה. קווים שממשיכים ולא נגעו: טעינה מחדש של
הכתובת בייצור מנתקת את הסשן; הקליטה מחברת 42 זכויות ל-`treatment` ואפס
ל-`info`/`reminder` על אותו `situation`; `decided_at` מלא עם `decided_by` null
אפשרי. `sent` בלתי-ניתן-להשגה בכוונה; `bkalot_clone_admin_create` אינה חשופה
ב-HTTP; `pdf`/`audio` → `channel_unsupported`. `public_visible` ו-`show_in_showcase`
של #37 נשארים `false`.
