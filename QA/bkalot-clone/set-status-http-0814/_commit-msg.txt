שכפול בקלות שכבה 3: להכרעת האדם לא הייתה ולו כתובת HTTP אחת שמסך הניהול יכול לפנות אליה (§5ב, v6)

0072 בנתה את bkalot_clone_admin_set_status ומדדה אותה במסד — תשע דחיות, ארבעה
מסלולים, updated_at שזז על שינוי וקפוא על לחיצה חוזרת — ושוב service_role בלבד.
כלומר סגירת פנייה קיימת כפונקציה, ואין ולו כתובת אחת שמסך הניהול יכול לפנות
אליה: אותו מצב בדיוק שבו היו queue לפני v4 ו-dispatch לפני v5. זו הכתובת.

מעבר לזה, המדידה של 0072 עצמה נאלצה לרוץ בקריאות SQL מהטרמינל כי לא הייתה דרך
אחרת. כאן כל 24 המדידות הן HTTP: הפניות נוצרו דרך bkalot-clone-intake עם מפתח
ה-anon של הטופס, והמצב הסופי נקרא בחזרה מ-/case ומ-/cases.

מה נבנה — נתיב אחד, POST /bkalot-clone-admin/set-status, מאחורי אותו שער בדיוק
כמו render/queue/dispatch. שלוש הכרעות:

* שם הנתיב במקף ולא setStatus ולא status. השני היה נקרא כמו קריאת קריאה בעוד
  שזה נתיב שכותב — וזה בדיוק מה שגורם למישהו לקרוא לו כדי «לבדוק».
* אין כאן ולו בדיקה אחת על ערך ה-status. רשימת ההיתר, הסירוב ל-sent ול-new
  וההבחנה בין status_unknown ל-status_not_settable יושבות במסד בלבד; עותק שני
  כאן היה נשאר מאחור ברגע ש-'sent' יהפוך לניתן-להשגה.
* admin חוזר בתשובה ואינו נשמר — 0072 אינה כותבת «מי שינה» לשום מקום, ולא
  הומצאה כאן טבלת יומן.

פריסה: version 6, ACTIVE, verify_jwt: true מוצהר במפורש.

נמדד מעל HTTP — השער: OPTIONS מחזיר 204 עם x-admin-token ב-allow-headers, בלי
טוקן 401 token_required, טוקן פגום עם גוף תקין 401 invalid_session. ארבעת
המסלולים על פנייה שהתחילה new: closed (changed=true), closed שוב
(changed=false), rejected, ואז in_progress בכינוי id וכמחרוזת. /case מחזירה
in_progress ו-/cases?status=in_progress מחזירה total=1 שמכילה את #71 ולא את
#72. הבקרה #72 נשארה new ו-updated_at שלה מוקדם ב-5.2 שניות למרות שנוצרה
אחריה. תשע דחיות, כולן מ-0072 ולא מקוד ה-edge.

מצב טסט: outbound_queue=8 ללא שינוי, delivery_log=3, documents=0, אפס פניות
ב-status='sent'. אין קריאה יוצאת אחת. המקור: 8 שורות app_key='bkalot' לפני
ואחרי, טביעת אצבע e491999e1492c0dcf1cf88288bdec60a זהה. הבדיקה התגלגלה אחורה
במלואה — cases=0, contacts=4, admin_users=1, זהה בדיוק לבסיס.

נשאר פתוח: אין כפתור ב-admin.html ואין פריסת פורטל, ולכן מנהל שפותח את המסך
עדיין אינו יכול לסגור פנייה. זו הפעימה הבאה. «מי שינה ומתי» עדיין אינו נכתב
לשום מקום.
