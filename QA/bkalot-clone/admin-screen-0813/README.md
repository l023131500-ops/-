## שלוש הכרעות שנגזרות מהמדידה ולא מטעם

**1. הטוקן בזיכרון בלבד — ורענון מנתק.** זה הדפוס שהועתק מהמקור
(`BKALOT_METHOD §6.2`), והמשמעות המעשית שלו נראית למשתמש. נמדד בדפדפן החי ולא
הונח: `sessionStorage` ריק, `document.cookie` ריק, ו-`localStorage` מחזיק חמישה
מפתחות — `kf_token`, `chatzor-gabai-syn`, `chatzor-theme`, `more30-admin-theme`,
`torah-platform-cart-v1` — **כולם של מערכות אחרות שיושבות על אותו origin**.
כלומר «localStorage ריק» אינה הבדיקה הנכונה כאן ולא הייתה עוברת; הבדיקה היא
שאין ולו מפתח אחד שהמסך הזה כתב.

**2. `401` הוא מצב ולא שגיאה שמוצגת.** נפילת שער מחזירה 401 (הכרעה של #224),
ולכן `call()` מאפס את הטוקן ומחזיר את המסך לכניסה במקום להציג פס אדום מעל רשימה
ריקה. הבחנה זו היא בדיוק מה ש-401-ולא-200 קנה.

**3. היציאה אינה ממתינה לשרת.** הטוקן משתחרר בלקוח ואז נשלחת בקשת `logout`
באוויר. `logout` אידמפוטנטי בשרת, ויציאה שנתקעת על שגיאת רשת היא בדיוק המסך
שהמשתמש אינו יכול לצאת ממנו. **נמדד שהיא בכל זאת הגיעה:** `admin_sessions` הראה
`revoked_at is not null` על הסשן, ושורת ה-audit מחזיקה IP ו-User-Agent אמיתיים
של הדפדפן — כלומר הבקשה יצאה, ולא רק המסך התנקה.

## מה שהמסך אינו עושה, ובכוונה

- **אין בו שום כתיבה.** אין שינוי סטטוס, אין הערה ואין שליחה — שש הפונקציות של
  שכבה 2 הן קריאה בלבד, והמסך אינו מתיימר ליותר.
- `contact:null` מוצג כ«— ללא איש קשר —» ואינו נעלם:
  `cases_contact_id_fkey` הוא `ON DELETE SET NULL`, ופנייה מיותמת שנשמטת מהרשימה
  נראית בדיוק כמו רשימה תקינה.
- קוד זכות שהתיישן (`in_catalog=false`) מוצג במפורש ואינו נבלע.
- כל העברית יושבת במילון אחד בלקוח. קוד שאין לו תרגום מוצג כפי שהוא, אחרת קוד
  חדש בשרת היה נעלם מהמסך.
