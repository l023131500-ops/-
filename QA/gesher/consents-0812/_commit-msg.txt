31 gesher: the "coming soon" screen on a live system, and the consent table nobody ever wrote to

/gesher/client/consents was six lines of PlaceholderPage — the third item in the
client area's sidebar led nowhere. This was open line (1) from run_progress #472.

Nothing was missing from the database. public.client_consents has existed since
the first migration, with a policy the client actually passes:

  FOR ALL USING (auth.uid() = client_id) WITH CHECK (auth.uid() = client_id)

Unlike client_profiles — the table #173 broke on, which has a SELECT-only policy —
a client may genuinely write their own row here. The app had simply never asked.

The category catalogue is not a list in the code. It is read from
public.visibility_rules, which every authenticated user may SELECT, along with
allowed_schema_fields — so the screen shows the customer exactly which of their
details each partner category would see. Two categories carry fields the admin
already ticked; the third says in as many words that none were configured.

The lesson from #173 was applied up front rather than after the fact:
setClientConsent does .select() and throws on zero rows, so a write RLS filters
out can no longer report ok:true, and a category that is not a visibility_rules
row is rejected before the write.

VisibilityRulesGrid carried its own copy of the category label map; both sides now
import src/lib/partner-categories.ts.
