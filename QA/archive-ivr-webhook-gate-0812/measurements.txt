     -> 200, 345 bytes

      "total_one_time_expenses":0,"monthly_balance":0,"net_balance":0},
      "pending_tasks":0,"tts_text":"..."}
     The uuid is invented, so the totals are zeros — the point is that the
     service_role query RAN for an anonymous caller. With a real user_id the
     same call returns that person's finances.

POST /ivr-api?action=login   {"id_number":"000000000","pin":"000000"}
     -> 401 {"error":"פרטי ההזדהות שגויים"}
     i.e. the profiles table was queried unauthenticated. This is a PIN oracle:
     6 digits, no rate limit, and a hit returns the user_id that unlocks every
     other action.

POST /inbound-webhook   {}
     -> 400 {"error":"Missing user_id or type"}
     i.e. reached the insert branch; a body naming a real user_id would have
     written transactions / chat_messages on the service role.

No response body containing a real person's data was ever requested or stored:
every probe used an invented uuid or deliberately wrong credentials.
