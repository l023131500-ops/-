# מודל המערכת — אתר תדמית → כניסה → מנוי

> המבנה שכל אחת מ-33 המערכות חייבת לעמוד בו. נגזר מהוראת המשתמש (31/07/2026)
> ומשלים את הגדרת "מוכן" ב-`MORE30_MASTER_BUILD.md §2`.
> **מאומת מקצה-לקצה על 16 חצור ועל 17 חיזוקים.**

---

## 1 · שכבות הכתובת

| כתובת | מה יושב שם | מי מגיש |
|---|---|---|
| `more30.com/<שם>` | **אתר תדמית שיווקי** | הפורטל (`system.html`) |
| `more30.com/<שם>/` | **המערכת עצמה** | פרויקט ה-Vercel של המערכת |
| `more30.com/<שם>/…` | מסכי המערכת | אותו פרויקט |
| `more30.com/subscribe?app=<שם>` | בחירת מסלול | הפורטל (`subscribe.html`) |
| `more30.com/login` · `/auth/callback` · `/me` | כניסה · נחיתה · אזור אישי | הפורטל |

**הפרדה בסלאש אחד.** זה מה שמאפשר עמוד תדמית לכל מערכת **בלי לבנות מחדש**
אף אפליקציה: ה-`basePath` שלהן נשאר `/<שם>`, והן ממשיכות לעבוד בדיוק כמו קודם.

---

## 2 · עמוד התדמית — נבנה פעם אחת, משרת את כולן

`portal/public/system.html` הוא קובץ אחד שמזהה את המערכת **מהכתובת עצמה**
וקורא את התוכן חי דרך `more30_system_page(app)`:

| מקטע | מקור הנתון |
|---|---|
| כותרת | `core.projects.name_he` |
| משפט פתיחה | `tagline` |
| "מה השירות עושה" | `what_it_does` |
| "מה יש במערכת" | `functions`, מופרד ב-`·` |
| מסלולים | `core.plans` (עם נפילה למסלולי הפלטפורמה) |
| "כניסה למערכת" | `https://more30.com/<שם>/` |

**אין בו טקסט שיווקי כתוב-בקוד.** שדה ריק במרשם = מקטע שלא מוצג. מערכת שאינה
`is_deployed` מקבלת "בהכנה" במקום כפתור כניסה, כדי שלא נשלח מבקר לדף מת.
המשמעות המעשית: שיפור הקופי של מערכת נעשה **במרשם**, לא בקוד, ומופיע מיד.

---

## 3 · הכניסה

1. "כניסה למערכת" → `/<שם>/`. המערכת נטענת; מי שכבר מחובר — מחובר (origin אחד).
2. הכפתור המשותף בנווט העליון קיים בכל אתר (`auth-button.js`), ומציג:
   אזור אישי · **ניהול** (רק למי שהשרת אישר) · **שדרוג** (למשתמש חינמי) · יציאה.
3. כניסה/הרשמה → `/login` → `/auth/callback`, שם נרשמת **חברות לאתר שממנו באת**
   (`core.app_memberships`) והמשתמש מוחזר לאותו אתר.
4. אחרי התחברות: משתמש רגיל → האזור האישי של אותו אתר; סופר-אדמין → ניהול.

## 4 · המנוי — זרימה מלאה, בלי סליקה

- `core.plans (app_key, code, name_he, tagline, price_ils, period, features)`.
  מערכת בלי מסלולים משלה יורשת את מסלולי הפלטפורמה, והמנוי נרשם תחת `more30`
  — כלומר **מנוי אחד שתקף בכל המערכות**. המסך אומר את זה במפורש.
- `core.subscriptions` — מנוי פתוח אחד לכל משתמש בכל מערכת (אינדקס ייחודי חלקי).
- `more30_subscribe(app, plan)` **רושמת בקשה ואינה מחייבת**. התשובה נושאת
  `charged:false` ומשפט מפורש, כדי שהמסך לא יוכל "לשכוח" להגיד את זה.
- מסלול חינמי אינו מנוי — הוא ברירת המחדל, ובחירה בו מוחקת בקשה פתוחה.

> ⚠️ **`price_ils` הוא NULL בכל המסלולים** ואינו מומצא. המסך מציג
> "המחיר טרם נקבע · נעדכן לפני שנפתחת הסליקה". מחירים אמיתיים → `NEEDS_USER`.

חיבור נדרים פלוס ייכנס בשלב הסליקה ויחליף את `requested` ב-`active` — הזרימה,
המסכים והמסד כבר בנויים סביב זה.

## 5 · שער הניהול — כלל אחד לכל המערכות

> **"אדמין מקומי של המערכת **או** סופר-אדמין גלובלי."** בלי יוצא מן הכלל,
> ובלי stub זמני. `public.more30_app_access(app)` מחזיר את שתי התשובות יחד.

- מערכת שיושבת על ההאב: השער קורא ישירות ל-RPC (ראה 16 חצור).
- מערכת על פרויקט Supabase אחר: **חיבור שני** להאב (anon בלבד) שרק שואל
  "האם המשתמש מנהל" (ראה 15 egod). **אסור** לחלוק `storageKey` עם מערכת כזו —
  JWT של ההאב אינו תקף שם וזה מנתק את המשתמשים הקיימים שלה.
- שער מבוסס-טוקן: מקבל **גם** סשן מאושר, דרך החלפה לעוגייה חתומה (ראה 32 נדל"ן).

## 6 · המתכון להוספת מערכת למודל

1. לוודא ש-`core.projects` מלא: `name_he`, `tagline`, `what_it_does`, `functions`.
2. ב-`portal/vercel.dist.json`, להחליף את השורה של המערכת בשלוש:
   ```json
   { "source": "/<שם>",        "destination": "/system.html" },
   { "source": "/<שם>/",       "destination": "https://<proj>.vercel.app/<שם>/" },
   { "source": "/<שם>/:path*", "destination": "https://<proj>.vercel.app/<שם>/:path*" }
   ```
3. לוודא שתג `auth-button.js` נמצא ב-**index.html שבמקור** (לא רק בעותק הפרוס).
4. לפרוס את הפורטל דרך `scripts/stage-portal.ps1`, ואז לאמת בדפדפן:
   `/<שם>` = תדמית · `/<שם>/` = המערכת · "כניסה למערכת" עובד.
5. מסלולים ייחודיים למערכת → שורות ב-`core.plans` עם ה-`app_key` שלה.

### 🪤 מלכודות ידועות
- **`/<שם>/` אינו נתפס על ידי `:path*`** (נמדד ב-gesher) — חייבים שורה נפרדת.
- **`:path*` ריק** אינו מטופל, ולכן בלי השורה הזו הכתובת נופלת ל-catch-all
  של הפורטל ומחזירה את דף הבית במקום את המערכת.
- **אפליקציות Next.js** (tamlul, modaot, orech, nadlan) מטפלות בסלאש עוקב
  בעצמן ועלולות להפנות `/<שם>/` בחזרה ל-`/<שם>` — שהוא עכשיו התדמית, כלומר
  לולאה. **לבדוק כל אחת מהן בנפרד לפני החלפת השורה.** לא הוחלו עדיין.
- **`vite build` מוחק תוספות ידניות ב-`index.html`** — ולכן סעיף 3.
