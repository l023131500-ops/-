## 16 — חצור קונקט: מה נעשה הלילה

הענף `claude/website-review-improve-idkpx0` (6 שלבים, 75 קבצים, 7,701 שורות)
ישב לא-ממוזג בזמן שהגרסה הישנה נשארה באוויר.

**מה בוצע:** מוזג ל-`main` (ול-`feature/unify-phase1`) · schema `chatzor` הוחל
על המסד המרכזי (13 טבלאות + RLS + הרשאות + חשיפה ב-PostgREST) · האפליקציה
נבנתה עם `BASE_PATH=/chatzor` (נוסף `basename` לראוטר, אחרת כל קישור פנימי היה
נופל לפורטל) · נפרסה לפרודקשן.

**אימות:** `chatzor-more30` READY · `more30.com/chatzor` מחזיר את הגרסה החדשה
(כותרת "מחוברים · חצור הגלילית", asset חדש) והישנה נעלמה · ה-bundle החי מצביע
למסד המרכזי, המסד הישן (`mwljkonwdeuaahsigjdp`, שכל טבלאותיו ריקות) כבר לא
מופיע בו · קריאה עם מפתח anon: `organizations=1`, `community_services=1`,
`synagogues=0`.

**החיבורים האמיתיים:**

**למה עדיין מוסתרת מהאתר:** התוכן הקהילתי ריק (0 בתי כנסת, 0 זמני תפילה,
0 שיעורים). הכתובת פעילה ונגישה, הפורטלים לניהול ולגבאים עובדים — ברגע
שיוזן תוכן, סימון תיבה אחד מחזיר אותה לרשימה הציבורית.

**מה נשאר לפתוח:**
1. **דחיפה ל-GitHub לא בוצעה** — אין טוקן זמין ב-shell (הסוד ששמור בקרדנשל
   מנג'ר של GitHub Desktop אינו טוקן שמישות ל-API; `git push` ביקש סיסמה
   וההרצה לא אינטראקטיבית). המיזוג והקומיטים קיימים מקומית על `main` ועל
   `feature/unify-phase1`. להשלמה, מהטרמינל שלך:
   `git push -u origin main && git push origin feature/unify-phase1`
   (או Push דרך GitHub Desktop). **הפריסה לא תלויה בזה** — היא נעשית ב-CLI.
2. **משתמש אדמין ראשון** לחצור: אחרי התחברות ראשונה, `insert into
   chatzor.org_admins (organization_id, user_id) select id, '<uid>' from
   chatzor.organizations where slug='chatzor-hagelilit';`
3. **Dashboard → API → Exposed schemas**: להוסיף שם `chatzor` (הוגדר ב-SQL;
   שמירה עתידית בדשבורד עלולה לדרוס את ההגדרה).
