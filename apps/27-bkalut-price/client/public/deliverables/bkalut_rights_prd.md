# PRD — בקלות מיצוי זכויות (Bkalut Rights)

מסמך מוצר עברי לפלטפורמת בקלות למיצוי זכויות. זהו "מקור האמת" לכל מה שקשור בזכויות, הטבות, עמותות, טפסים, לידים, ואינטגרציות n8n/מערכת קולית.

---

## 1. הצהרת בעיה (Problem Statement)

אזרחים, משפחות ובעלי עסקים בישראל מאבדים מדי שנה אלפי שקלים בגין זכויות והטבות שאינם ממצים: ביטוח לאומי, מס הכנסה, ארנונה, רשויות ממשלתיות, קופות חולים, עמותות, מעסיקים. הסיבות:

- ריבוי גופים, חוקים ותקנונים — אין מסך אחד שמרכז את הכל.
- שפת הטפסים בירוקרטית, חסומה למי שלא מתמצא.
- חוסר הנגשה למגזרים שאינם מקוונים (חרדים, מבוגרים, אנשים בלי שליטה במחשב).
- חוסר ידע מי הגורם המוסמך וכיצד מגישים.

החזון: הופכים את מיצוי הזכויות לתהליך פשוט, אוטומטי, נגיש בקול ובכתב, עם ליווי אנושי במקום הצורך.

---

## 2. מטרות (Goals)

1. שכל משתמש יזהה לפחות 3 זכויות לא ממומשות עבורו בתוך 5 דקות.
2. הקטנת זמן המעבר מ"זיהוי זכות" ל"הגשת טופס/פנייה לעמותה" לפחות פי 5.
3. מאגר מקיף ועדכני (יותר מ-500 זכויות ו-200 עמותות) עם רענון חודשי אוטומטי.
4. ערוצי כניסה מרובים: אתר, ווטסאפ, מייל, מערכת קולית (IVR), פודקאסט קולי, פנייה דרך נציג קהילתי.
5. ממשק ניהולי פנימי לצוות בקלות לעדכן, לעקוב אחרי לידים, ולהפעיל אוטומציות.

### מטרות עסקיות

- בניית מאגר נתונים שמהווה IP יחודי ומוגן.
- מנוע ליצירת לידים והפניות לשירותי הליווי בתשלום.
- בסיס לאינטגרציות עם המוצר השני (ניהול פיננסי מבית בקלות) דרך API/Webhook.

---

## 3. דברים שאינם במטרה (Non-Goals)

1. **לא מהווה ייעוץ משפטי/רפואי/פיננסי**. אנו מציגים מידע פומבי ומסייעים בבירוקרטיה בלבד.
2. **אין הבטחה לאישור תביעות**. כל זכות נבחנת לגופה על ידי הגוף הרלוונטי.
3. **לא נחליף הליך משפטי, ערעור, או ייצוג בבית דין**.
4. **לא נעשה תשלומים בשם הלקוח** ולא ננהל את הכספים שלו (זה תפקיד המוצר הפיננסי).
5. **אין שמירת מסמכים רגישים מעבר למה שהלקוח מאשר במפורש**, ואין שיתוף עם צד ג׳ ללא הסכמה.

## 4. דמויות משתמש (Personas)

| דמות | תיאור | צורך מרכזי |
|---|---|---|
| **משפחה צעירה / הורים** | זוג עם ילדים, הכנסה ממוצעת | זכויות חינוך, ביטוח לאומי, ארנונה, הנחות לבני נוער |
| **בעל עסק קטן** | עוסק פטור/מורשה, עד 5 עובדים | זכויות עסקיות, החזרי מס, הטבות מע"מ, מענקי קורונה/קליטה |
| **אדם עם מוגבלות / בני משפחה** | משפחה עם ילד נכה / מבוגר תלוי | קצבאות, מתקני נגישות, עמותות תמיכה |
| **מבוגר / פנסיונר** | אזרחים ותיקים | קצבת זקנה, גמלת סיעוד, מימוש פנסיה, הנחות |
| **מגזר חרדי / שאינו מקוון** | מעדיף ערוץ קולי וווטסאפ | פנייה בעברית פשוטה, מערכת קולית, נציג קהילתי |
| **נציג קהילתי / מתנדב** | מסייע לאחרים | פורטל פנימי ליצירת פניות מרוכזות |
| **צוות בקלות (אדמין)** | עובדי הארגון | ניהול לידים, עדכון נתונים, הפעלת אוטומציות |

## 5. סיפורי משתמש (User Stories)

### P0 — חובה

- כמשתמש סופי, אני רוצה להזין מצב משפחתי/כלכלי בסיסי ולקבל רשימת זכויות מתאימות עם הסבר ולמה מגיע לי, כדי שאדע מה להגיש.
- כמשתמש, אני רוצה ללחוץ על "אני רוצה עזרה" בזכות מסוימת ולקבל יצירת פנייה אוטומטית עם פרטיי לצוות בקלות.
- כמשתמש שאינו מקוון, אני רוצה להתקשר למערכת קולית (02-3131500) ולשמוע פודקאסטים מסודרים לפי נושאים.
- כצוות בקלות, אני רוצה לראות את כל הלידים והפניות במסך אחד, לסנן, לעדכן סטטוס, ולהקצות לאחראי.
- כצוות בקלות, אני רוצה לעדכן מאגר הזכויות והעמותות מקובץ Excel או Google Sheets (פעם בחודש).

### P1 — חשוב

- כמשתמש, אני רוצה לשלוח הודעת WhatsApp/מייל עם תיאור חופשי ("שילמתי 300 לחשמלאי, מגיע לי החזר?") והמערכת תזהה אוטומטית.
- כמשתמש, אני רוצה לקבל תזכורות אוטומטיות (לפי חודש, אירוע משפחתי, גיל ילד) על זכויות שהזמן שלהן מתקרב.
- כצוות בקלות, אני רוצה לייצא דוחות חודשיים על פניות, זכויות מצליחות, וערוצי המשך.

### P2 — אופציונלי

- אינטגרציה עם מערכות גוגל קלנדר/אאוטלוק לתזכורות.
- חתימה דיגיטלית על ייפויי כוח דרך המערכת.

## 6. דרישות (Requirements)

### P0

1. **מאגר זכויות** — שדות חובה: כותרת, קטגוריה, חוק/תקנה מקור, גוף מנפיק, תנאי זכאות, סכום/הטבה, מסמכים נדרשים, קישור לטופס, סטטוס עדכון.
2. **מאגר עמותות וארגונים** — שם, התמחות, אזור, יצירת קשר, טפסים שמובילים אליהם.
3. **קטגוריות** (קיימות במסך הניהול):
   - ביטוח לאומי וקצבאות
   - דיור, שכירות ומשכנתאות
   - ילדים, חינוך ומעונות
   - בריאות וקופות חולים
   - מס הכנסה והחזרים
   - עבודה, פנסיה ופיצויים
   - הנחות בתשלומים (ארנונה, חשמל, מים)
   - חובות והוצאה לפועל
   - נושאים נוספים (מגזר חרדי, ניצולי שואה, אנשים עם מוגבלות, מבוגרים)
4. **בדיקת התאמה** — שאלון קצר (גיל, מצב משפחתי, ילדים, הכנסה, מעמד דיור, בריאות) → ציון התאמה לכל זכות.
5. **טפסי שירות** — לכל זכות/קטגוריה, אפשרות להפעלת טופס שירות שנשלח ל-n8n webhook (`https://n8n.l023131500.work/webhook/NEDARIM3873`) ונרשם פנימית.
6. **מסך פניות (Submissions)** — צוות בקלות רואה כל פנייה, יכול להעביר לסטטוס "בטיפול / נשלח / נסגר", להוסיף הערות.
7. **אינטגרציות**:
   - n8n Webhook (קיים)
   - מערכת קולית / IVR (פודקאסט בשלוחה 7, פנייה בשלוחה אחרת)
   - WhatsApp Inbound (n8n)
   - מייל נכנס (n8n)
8. **גישה פנימית/דמו** — תיוג ברור של "כלי פנימי לצוות בקלות". משתמש דמו: `l023131500@gmail.com` או טלפון `023131500` + קוד `123456` (ראה אזהרת אבטחה במסמך תנאים).
9. **RTL מלא, עברית, נגישות AA**.

### P1

- מנוע התאמה מתקדם עם משקלים (לא רק filter אלא ranking).
- צ׳אטבוט ציבורי (Public Concierge Bot) שמכוון לזכות מתאימה.
- ייצוא XLSX של זכויות לפי קטגוריה (קיים).

### P2

- חיפוש סמנטי בעברית.
- סיכום קולי אוטומטי לפודקאסט מתוך טקסט הזכות.

## 10. אוטומציות (Automations)

| ערוץ | פירוט |

| **Rights API** | נקודת קצה פנימית שמשרתת את האפליקציה הפיננסית: `GET /api/rights/match?profile=…` → רשימת זכויות מומלצות. |

## 12. סנכרון עם המוצר הפיננסי

הקשר עם "ניהול פיננסי מבית בקלות" מפורט במסמך `bkalut_financial_integration_prd.md`. בעיקרון:

- **בקלות זכויות = מקור האמת לזכויות**. הפיננסי קורא דרך API.
- **הפיננסי מזהה הזדמנות זכות** מתוך התנהגות (הוצאה גדולה לחשמלאי → אולי החזר; הוצאה רפואית → אולי עזרה), שולח prompt למשתמש: "להעביר לבקלות לבדיקה?" → אם כן, נוצר `submission` אצלנו.
- **לא משכפלים נתונים פיננסיים** — בקלות זכויות לא מאחסנת תקציבים.

## 13. קריטריונים לקבלה (Acceptance Criteria)

### לדוגמה — בדיקת התאמה (Match)

- **Given** משתמש פתח את `/match` ומילא: גיל 35, נשוי+3 ילדים, מעמד דיור = שוכר, הכנסה 12,000 ש"ח.
- **When** הוא לוחץ "חשב התאמה".
- **Then** המערכת מחזירה לפחות 8 זכויות מ-3 קטגוריות שונות, ממוינות לפי ציון התאמה (0–100), כל אחת עם כפתור "בקש עזרה".

### לדוגמה — שליחת פנייה

- **Given** משתמש בדף זכות "החזר ארנונה".
- **When** הוא לוחץ "אני רוצה עזרה", ממלא שם/טלפון/מייל, מאשר תנאים.
- **Then** נוצר record ב-`submissions` עם status=new; נשלח POST ל-n8n; ב-UI מופיע "נקלטה פנייה מס׳ #1234".
- **And** ב-`/submissions` הצוות רואה את הרשומה החדשה בראש הרשימה.

### לדוגמה — ייצוא XLSX

- **Given** אדמין בדף זכויות עם פילטר קטגוריה = ביטוח לאומי.
- **When** לוחץ "ייצא XLSX".
- **Then** מורד קובץ עם רק הזכויות המסוננות, כולל כל השדות, ובשמות עברים תקינים.

## 14. סיכונים (Risks)

1. **דיוק המידע** — חוקים משתנים. דורש רענון חודשי + תיוג "אומת לאחרונה".
2. **פרטיות** — מידע רגיש (מצב משפחתי, בריאותי, כלכלי). חובת הצפנה במנוחה ובמעבר, גישה מבוקרת.
3. **הסתמכות יתר** — משתמש עלול לראות "אתם אישרתם שמגיע לי" → חשוב מסר ברור שזו הערכה ולא החלטה משפטית.
