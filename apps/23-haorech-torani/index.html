עוזר עריכה חכם לספרים תורניים: מזהה ומאמת ציטוטים מול המקור, מנקד טקסט רבני, מציע כותרות ומראי-מקום בפורמט המקובל — הכל בעקרון של אפס הזיות: כל מקור נשלף ממאגר אמין, לא מ״זיכרון״ המודל.

01 · הפונקציות

שבע הפונקציות של העורך התורני

לכל פונקציה — התיאור המקצועי ואופן הביצוע הטכני המומלץ, על בסיס המפרט המקורי והמחקר שנעשה על כלים ומאגרים קיימים.

1

זיהוי ציטוטים אוטומטי

איתור מראי-מקום מקראיים, תלמודיים והלכתיים בתוך טקסט חופשי — כולל ציטוטי ״שם״ ומקרים אמביגואליים.

ביצוע: Sefaria Linker API (POST /api/find-refs, מנוע BERT עברי) + DICTA Citation Finder כשכבה משלימה.
2

אימות מקורות מול הטקסט

שליפת הטקסט המקורי לפי ה-Ref שזוהה והשוואתו לציטוט — התאמה מדויקת או מקורבת, עם הצגת ההבדל.

ביצוע: Texts API (with_text=1) + השוואת diff/Levenshtein + embeddings סמנטיים; פלט: תואם / סטייה / לא נמצא.
3

ניקוד אוטומטי לטקסט רבני

ניקוד מותאם לעברית רבנית וארמית תלמודית — לא רק עברית מודרנית — עם טיפול בשמות קודש וכתיב מלא/חסר.

ביצוע: DICTA Nakdan רבני (Genre=rabbinic) כברירת מחדל; D-Nikud/MenakBERT כגיבוי קוד-פתוח.
4

הגהה תורנית

שגיאות כתיב ונוסח, פענוח ראשי-תיבות, שמירה על מוסכמות הכתיבה התורנית — בלי לתקן טקסט מצוטט אלא לסמן חשד לשיבוש.

ביצוע: DICTA Abbreviation Expander + Hspell; סטיות מהמקור מסומנות בסוגריים, לא נמחקות.
5

פורמט מראי-מקום מקובל

המרת מ״מ קנוני (אנגלי) לפורמט התורני המסורתי: ״סנהדרין כ״ו ע״ב״, ״שו״ע או״ח סי׳...״, ״רמב״ם הל׳ שבת פכ״ב״.

ביצוע: שכבת נרמול דו-כיוונית בין Ref של ספריא לתבניות הפורמט התורני (טבלת Regex/NER ממופה).
6

המלצת כותרות ותתי-כותרות

סיכום מונחה-מבנה: זיהוי חלוקה טבעית של הטקסט (נושא, סוגיה, פרשה) והצעת כותרת בסגנון הסוגה (״בענין...״, ״בביאור שיטת...״).

ביצוע: LLM עם system-prompt מכוון-סגנון + אימות NER הלכתי מול DictaBERT/BEREL.
7

בקרת אדם (Review & Approve) בכל שלב

אף מודל אינו מגיע ל-100% דיוק — ובטקסט תורני קדוש טעות היא כישלון חמור. לכן כל פעולה (ניקוד, ציטוט, כותרת) עוברת אישור אנושי עם הצגת חלופות מדורגות לפי סבירות. זה גם המודל שדיקטה עצמה נוקטת ב-Nakdan Pro.

עיקרון-על: אוטומציה מלווה, לא אוטומציה עיוורת — הטקסט המקורי לעולם אינו משתנה ללא אישור מפורש.
02 · שכבות העיבוד

מסלול הטקסט במערכת

כל קטע טקסט עובר שרשרת עיבוד דטרמיניסטית שבה שכבת השליפה (אמינה) מופרדת משכבת הניסוח (יצירתית) — עיקרון-הליבה נגד הזיות.

1

טעינת טקסט

הזנת הטקסט (הדבקה / העלאת קובץ / OCR דרך DICTA Maivin לדפים סרוקים). זיהוי גבולות פסקאות ויחידות טבעיות.

2

זיהוי ציטוטים

הרצת find-refs על הטקסט — קבלת רשימת מ״מ מזוהים עם טווחי-תווים ורשימת Refs אפשריים לכל אחד.

3

אימות מול המקור

לכל Ref — tool call חובה לשליפת הטקסט האמיתי, השוואה מדויקת+מקורבת, וקביעת סטטוס אמון.

4

ניקוד והגהה

ניקוד רבני (Nakdan) + פענוח ראשי-תיבות + בדיקת כתיב — הכול כהצעות הניתנות לעריכה, לא כשינוי סופי.

5

נרמול פורמט

המרת ה-Refs לפורמט המראה-מקום התורני המקובל, והכנת הערות/סוגריים לפי מוסכמות ההגהה.

6

בקרת אדם ואישור

העורך רואה כל שינוי מוצע לצד המקור, מאשר/דוחה/מתקן — ורק אז השינוי נכתב. הטקסט הקדוש נשמר תמיד.

04 · ארכיטקטורה

RAG לתורה — ושכבת ה-anti-hallucination

RAG על טקסט תורני שונה מ-RAG כללי: החלוקה (chunking) היא לפי יחידת מ״מ טבעית (פסוק, דף, הלכה) ולא לפי גודל טוקנים קבוע.

שכבת נתונים — Supabase + pgvector

טעינת Sefaria-Export ל-Postgres מקומי (לא תלוי ב-rate limits חיצוני). טבלה עם ref, text_he, category_path, embedding vector(N) ואינדקס HNSW.

pgvectorHNSW indexHybrid search (BM25 + vector)

שכבת שליפה (Retrieval) — דטרמיניסטית ואמינה

Chunking לפי Ref, מטא-דאטה עשירה, retrieval דו-שכבתי: חיפוש סמנטי (embeddings) + חיפוש גרפי לפי הקישורים של ספריא (Links API). כאן — ורק כאן — מגיעה כל ״עובדה״.

Chunking לפי מ״מLinks graphRe-ranking (cross-encoder)

שכבת ניסוח (Generation) — LLM עם tool-use בלבד

ה-LLM אסור לצטט מ״זיכרון״; חובה עליו לבצע tool call ולצטט רק את מה שהתקבל. פלט מובנה (JSON: {claim, ref, exact_quote, confidence}) לאימות מכני, ואימות second-pass לאחר ההפקה.

Function calling חובהStructured outputPost-hoc verification

העיקרון הקריטי: ״הספר פתוח לפניו״

הזיית מקור בטקסט תורני — ציטוט לא-קיים או שגיאה בשם חכם — היא כישלון חמור, לא רק טכני. לכן המערכת מבוססת על שליפה אמינה ולא על ידע פנימי של המודל, בדיוק כפי ש-Sefaria MCP מנסח: ה-AI אינו ״ממציא״ את הציטוט אלא ״שותף שהספר פתוח לפניו״.

מקורות: Supabase pgvector · Sefaria MCP · Sefaria Linker API

06 · תוכנית המימוש

מה למסור לקלוד — לפי שלבים

תוכנית בנייה מדורגת: תשתית קודם, יכולות אחר-כך. שכבת החינם (Sefaria+DICTA) מספקת 5 מתוך 7 הפונקציות כמעט ללא עלות; שכבת ה-AI המלאה נבנית מעליה.

א

תשתית ופרויקט

Next.js + Supabase (schema, pgvector) → Vercel. מפתחות ה-API כ-Environment Variables של המשתמש (כדי שיישמרו וימשיכו לעבוד עם קלוד), דומיין אמיתי ללא proxy — תאימות ל-NetFree.

ב

טעינת מאגר טקסטואלי

ייבוא Sefaria-Export ל-Postgres, בניית אינדקס Refs וקישורים, יצירת embeddings לכל chunk. בדיקת שדה license לכל ספר לפני שילוב.

ג

שכבת חינם — 5 פונקציות

זיהוי ציטוטים (Linker), אימות מקורות, ניקוד (Nakdan), פענוח ראשי-תיבות, נרמול פורמט מ״מ — כולן על בסיס Sefaria+DICTA כמעט ללא עלות.

ד

שכבת פרימיום — AI מלא

המלצת כותרות, RAG סמנטי מלא, סיוע חכם — עם Claude/Gemini/BEREL ו-tool-use מחייב. בקרת עלויות לפי שכבת מנוי.

ה

עורך דו-תצוגה + בקרת אדם

ממשק Review-and-Approve: מקור מול הצעה, חלופות מדורגות, אישור/דחייה לכל שינוי. עיקרון-על — הטקסט הקדוש לעולם אינו משתנה ללא אישור.

העורך התורני

מסמך ארכיטקטורה ותוכנית מימוש למערכת AI לעריכה, הגהה, ניקוד ואימות מקורות בספרים תורניים. מבוסס מחקר מעמיק על מאגרים תורניים דיגיטליים, כלי NLP עבריים וארכיטקטורות RAG.
