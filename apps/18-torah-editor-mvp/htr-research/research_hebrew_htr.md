# מחקר: המרת כתב יד עברי (HTR) ל"העורך התורני"
### הדרך להגיע לתוצאה החזקה בעולם לזיהוי כתב יד עברי — עכשווי והיסטורי

מסמך מחקר · יולי 2026

---

## 0. תקציר מנהלים (TL;DR)

**השאלה:** מהי הדרך החזקה ביותר בעולם להמיר כתב יד עברי לטקסט דיגיטלי, לשילוב כרכיב ב"העורך התורני"? העדיפות הראשונה — **כתב יד עכשווי** (הערות, טיוטות); העדיפות השנייה — **כתבים עתיקים/היסטוריים**.

**המסקנה המרכזית:** אין "מנוע קסם" יחיד. התוצאה החזקה בעולם לעברית מושגת דרך **צינור היברידי (hybrid pipeline)** בשלושה שלבים:

1. **מנוע HTR לא-גנרטיבי** (Kraken/eScriptorium בקוד פתוח, או Transkribus מסחרי) כמנוע ראשי — אמין, לא ממציא טקסט.
2. **אימון מודל מותאם אישית** על כתב היד הספציפי (50–150 עמודים ground truth) — זה מה שמקפיץ את הדיוק מ-30% ל-93%+.
3. **תיקון-אחר (post-correction) באמצעות LLM עברי** (DictaLM 2.0 בקוד פתוח, או Claude/Gemini) כשכבת ליטוש — מעלה ל-CER קרוב לאנושי (~1.8%).

**אזהרה קריטית:** מודלי VLM גנרטיביים (GPT-5, Claude Opus, Gemini 3) מובילים את דירוגי זיהוי כתב היד באנגלית (~1.2–1.5% CER), אבל **"לא עקביים באופן פרוע על כתבי יד רבניים" ו"ממציאים טקסט בשקט"** — מסוכן להשתמש בהם כמנוע ראשי לעברית. תמיד לזווג עם OCR לא-גנרטיבי לאימות צולב. ([מדריך OCR עברי 2026, mf-sr.com](https://mf-sr.com/en/blog/ocr-hebrew-2026-practitioner-guide.html))

**המלצה ל"העורך התורני":** להתחיל עם **eScriptorium + Kraken** (קוד פתוח, self-hosted, RTL מובנה, תואם NetFree לחלוטין) + **DictaLM 2.0** לתיקון (קוד פתוח, עברי). זה נותן פרטיות מלאה, אפס תלות בענן זר, ועלות תפעולית שוליית. עבור משתמשים שרוצים דיוק מקסימלי ללא תשתית — Transkribus כשירות ענן (€99/שנה).

## 1. הבנת האתגר: למה כתב יד עברי קשה

### 1.1 שלוש שכבות קושי

| שכבה | תיאור | דוגמה |
|---|---|---|
| **קושי כללי בכתב יד** | כל HTR קשה יותר מ-OCR של דפוס — צורות אותיות משתנות בין כותבים | הערות אישיות, טיוטות |
| **קושי ייחודי לעברית** | RTL, אותיות סופיות, ניקוד אופציונלי, אין רווחים ברורים, כתב רש"י/סת"ם | כתב יד רבני |
| **קושי היסטורי** | דהייה, כתמים, ריבוי ידיים, קיצורים (ר"ת), שפות מעורבות (עברית/ארמית/יידיש/לאדינו) | פנקסי קהילה, כתבי יד ימי-ביניימיים |

### 1.2 מציאות הדיוק — מספרים אמיתיים

הטבלה הבאה (מ[מדריך OCR עברי 2026](https://mf-sr.com/en/blog/ocr-hebrew-2026-practitioner-guide.html)) היא הנתון החשוב ביותר במסמך. היא מראה **דיוק לפי סוג חומר**, ומדגישה כמה אימות (training) קריטי:

| סוג חומר | ללא אימון (off-the-shelf) | אחרי 500 שורות אימון | אחרי 5,000 שורות |
|---|---|---|---|
| דפוס עברי מודרני נקי | 95–98% | 98–99% | 99%+ |
| דפוס רבני מהמאה ה-19 | 70–82% | 92–96% | 97–99% |
| דפוס יידיש אמצע המאה ה-20 | 80–90% | 95–98% | 98–99% |
| **מכתב עברי בכתב יד אישי, מאה 20** | **30–55%** | **80–90%** | **93–97%** |
| **כתב יד רבני, מאה 18–19** | **15–35%** | **70–85%** | **90–95%** |
| לאדינו בכתב רש"י | 40–60% | 85–93% | 95–98% |
| פנקס קהילה בריבוי ידיים | 20–40% | 65–80% | 85–93% |

**המסקנה:** עבור כתב יד, המנוע פחות חשוב מ**האימון**. "500 השורות הראשונות של ground truth מרימות את הדיוק בצורה עצומה. 4,500 השורות הבאות מביאות אותך מ'שימושי' ל'ראוי לפרסום'. מעבר ל-10,000 שורות אתה נלחם בתשואה פוחתת."

### 2.2 פירוט המנועים המובילים

#### eScriptorium + Kraken — הבחירה המומלצת ל"העורך התורני"
- **מהו:** פלטפורמת HTR בקוד פתוח שנבנתה על ידי קהילת מדעי הרוח הדיגיטליים. Kraken הוא מנוע ה-OCR/HTR; eScriptorium הוא ממשק העבודה (ניתוח פריסה, תמלול, אימון, human-in-the-loop).
- **חוזקות:** "הטוב ביותר בקוד פתוח ל-HTR על עברית היסטורית — ברגע שאתה מקבל שאתה מאמן מודל משלך." תמיכת RTL מובנית, רץ על GPU של לפטופ, נמצא בשימוש ב-BnF, École des Chartes ובאופן גובר בישראל. ([mf-sr.com](https://mf-sr.com/en/blog/ocr-hebrew-2026-practitioner-guide.html))
- **מודלים קיימים לעברית:** מודל **BiblIA** הכללי לכתב מרובע ימי-ביניימי >97% דיוק תווים (202 עמודים אימון). פרויקט **Sofer Mahir** מספק מודלים מוכנים: "עברית ימי-ביניימית מוכללת", Ashkenazi_01, Italian_01, Sephardi_01. ([GitHub dstoekl/sofer_mahir](https://github.com/dstoekl/sofer_mahir))
- **פרטיות:** self-hosted מלא → **תואם NetFree מושלם**, שום נתון לא יוצא החוצה.

#### Transkribus — הבחירה המסחרית לדיוק מקסימלי ללא תשתית
- **מהו:** פלטפורמת HTR מקצועית של READ-COOP, מבוססת ענן, תשלום-לפי-עמוד, עם UI מלוטש לאימון.
- **חוזקות:** "התשובה הנכונה כשצריך לשלב אנשים לא-מהנדסים בלולאת האימון והבדיקה." מודלי עברית/יידיש מתפתחים מהקהילה, כולל **DiJeSt 3.0** (העדכני). ([transkribus.org/hebrew](https://www.transkribus.org/hebrew-manuscript-transcription))
- **תמחור מאומת (2026):** תוכנית חינם 50 קרדיטים/חודש; Scholar €99/שנה; Team €399/שנה. **1 קרדיט = עמוד כתב יד אחד** (0.5 לדפוס). חבילות תוספת החל מ-€199/1,000 עמ'. **הנחת API של 50%** לתוכניות ארגוניות. ([transkribus.org/pricing](https://www.transkribus.org/pricing), [transkribus.org/credits](https://www.transkribus.org/credits))
- **חיסרון:** ענן חיצוני → פחות מתאים לדרישת NetFree/פרטיות מוחלטת.

#### DICTA — הנכס הישראלי הייחודי
- **מהו:** מרכז ישראלי (עמותה) לניתוח טקסט עברי, בראשות פרופ' משה קופל. כלים חינמיים ובקוד פתוח.
- **הישגים ב-OCR:** השלימו OCR של **כל אוסף שו"ת "פרי עץ חיים"** — לראשונה נגיש דיגיטלית עם חיפוש, ניקוד וקישורים למקורות. אפליקציית **Dicta Illuminate/Maivin**: צילום עמוד → זיהוי מקור מדויק + דיגיטציה + ניקוד + פתיחת ר"ת + הערות שוליים אוטומטיות. ([dicta.org.il](https://dicta.org.il/?lang=en), [Jerusalem Post](https://www.jpost.com/business-and-innovation/article-713942))
- **DictaLM 2.0:** מודל שפה גנרטיבי לעברית רבנית ומודרנית (decoder-only, מבוסס Mistral) — **קוד פתוח, זמין ב-GGUF ל-self-hosting**. אידיאלי כשכבת תיקון-אחר. ([huggingface.co/dicta-il/dictalm2.0](https://huggingface.co/dicta-il/dictalm2.0))

### 3.2 הצינור האקדמי המתקדם (transfer learning + LM correction)

מאמר מפתח מ-2025 ([ACL Anthology, aclanthology.org/2025.ldk-1.18](https://aclanthology.org/2025.ldk-1.18.pdf)) מציג צינור שמשפר משמעותית תמלול כתבי יד עבריים:
- **Transfer learning:** fine-tune מודלים מאומנים-מראש על **העמודים הראשונים בלבד** של כל כתב יד → שיפור **18% בדיוק תווים**.
- **תיקון-אחר מבוסס text-reuse:** ניצול הישנות טקסטואלית (נפוצה בכתבי יד ימי-ביניימיים) + LLM עברי (DictaLM) → שיפור **10% בדיוק ברמת מילה**.
- מטפל בתמלולים רועשים ומציע קריאות חלופיות טובות יותר.

### 3.3 תיקון-אחר ב-LLM מגיע לדיוק כמעט-אנושי

מחקר ([arxiv 2411.03340](https://arxiv.org/pdf/2411.03340.pdf)) מראה שתיקון פלט HTR באמצעות LLM מגיע ל-**CER 1.8% / WER 3.5%** — קרוב לרמה אנושית. זה מאשר את ארכיטקטורת ה-3 שלבים.

## 4. הצינור ההיברידי המומלץ (Order of Operations)

מבוסס על ["סדר הפעולות שבאמת עובד"](https://mf-sr.com/en/blog/ocr-hebrew-2026-practitioner-guide.html), מותאם ל"העורך התורני":

```
1. לכידת תמונה     →  400+ DPI, תאורה עקבית
2. עיבוד מקדים     →  יישור, ניקוי עיוותים, נורמליזציית ניגודיות
3. ניתוח פריסה     →  זיהוי עמודות, שוליים, הערות (Kraken segmentation)
4. HTR לפי אזור    →  Kraken/Transkribus + שמירת ציוני ביטחון (confidence)
5. זיהוי שפה       →  עברית / ארמית / יידיש → ניתוב למודל המתאים
6. תיקון-אחר LLM   →  DictaLM 2.0 / Claude, משוקלל לפי ביטחון-לפי-שורה
7. בקרת איכות QA   →  תור בדיקה אנושית מתועדף לפי ביטחון (5% במקום 30% אקראי)
                      → התיקונים מוזנים בחזרה לאימון המודל
```

**עקרון triage קריטי:** "90% הזולים והקלים מעובדים בקנה מידה; 10% הקשים — שם הערך ההיסטורי חי — נבדקים ידנית, והתיקונים מוזנים חזרה לאימון." פרויקט שבודק 5% מהעמודים לפי ביטחון יעלה על פרויקט שבודק 30% אקראית.

### 5.2 התאמה לתשתית הקיימת (Supabase / Next.js / Vercel)

| רכיב | מימוש מוצע | הערה |
|---|---|---|
| **אחסון תמונות** | Supabase Storage bucket | תמונות מקור + ground truth |
| **מנוע HTR** | Kraken API על שרת GPU נפרד (self-hosted) או Runpod/מכונה ייעודית | לא רץ ב-Vercel serverless — צריך GPU |
| **תיקון-אחר** | DictaLM 2.0 GGUF (self-host) או Claude API (למנויים פנימיים) | מפתחות נשמרים ב-env, תואם NetFree |
| **סכמת DB** | טבלת `htr_jobs` ב-schema `otvedaf`: image_url, status, raw_text, corrected_text, confidence_scores (jsonb) | integration עם ה-DB הקיים |
| **עורך תיקון** | קומפוננטת React RTL עם highlight לפי ביטחון | "הטקסט קדוש" — כל תיקון דורש אישור אנושי |

| **מנוי פנימי** | Transkribus API (דיוק מקסימלי) + מודל מותאם אישית | Claude Opus / Gemini 3 (החזק ביותר) | "המערכות החזקות ביותר לעברית" |

## 6. תוכנית יישום מדורגת (Roadmap)

### שלב א' — MVP (הוכחת יכולת)
- הקמת שרת Kraken/eScriptorium (Docker, self-hosted).
- טעינת מודלי Sofer Mahir + BiblIA המוכנים.
- endpoint פשוט: תמונה → טקסט גולמי → עורך RTL.
- **מטרה:** להוכיח 90%+ על כתב מרובע ברור.

### שלב ב' — אימון מותאם + תיקון LLM
- איסוף 50–150 עמודי ground truth של כתב היד היעד (העכשווי).
- אימון מודל Kraken מותאם → קפיצה ל-93%+ על כתב יד אישי.
- שילוב DictaLM 2.0 לתיקון-אחר.
- **מטרה:** להביא כתב יד עכשווי מ-30% ל-90%+.

### שלב ג' — כתבים עתיקים + QA loop
- הוספת מודלים לכתבי יד היסטוריים (Ashkenazi/Sephardi/Italian).
- תור QA מתועדף לפי ביטחון + feedback loop לאימון.
- אינטגרציה עם Sefaria Linker / DICTA לזיהוי מקורות.

### שלב ד' — הרחבה
- ניתוב לפי שפה (עברית/ארמית/יידיש/לאדינו).
- מנוע VLM אופציונלי (Claude/Gemini) למנויים פנימיים לעמודים קשים במיוחד — **תמיד עם אימות צולב**.
